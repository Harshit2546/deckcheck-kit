DeckCheck

Every claim in a pitch deck, checked against live data before the second meeting.

Each claim gets a verdict chosen by code, with its source and the record’s own date. The founder email waits for a person to approve it.

The job it replaces

Before a fund meets a startup a second time, an analyst checks the deck’s facts: team size, funding rounds, customers, market size, founders’ past jobs. That takes 3 to 8 hours per deck. DeckCheck does that check from the PDF to a drafted founder email, and asks a person only before the email is sent.

The AI never decides

The LLM lists claims and copies one sentence from a page. Python rules pick every verdict from tolerances in one config file.

Every fact is dated

Each evidence row keeps the URL or endpoint, exact field or quote, the record’s date and when it was fetched. Nothing dated after the deck counts.

Slow means held

A timeout, error or spent budget makes a claim Held with a reason, never Cannot verify.

Sent exactly once

approved, sending, sent in one transaction with a unique key on the inbox row. No mail code exists.

Five verdicts

VerdictMeaning
SUPPORTEDA dated record agrees with the claim within the tolerance in rules.yaml.
CONTRADICTEDA dated record disagrees by more than the tolerance.
NOT COMPARABLEThe record measures something else, is too old, or is dated after the deck.
CANNOT VERIFYNo record settles it. The report names what would.
HELDA timeout, an error or a limit. A slow source is never read as a missing one.

Trust, privacy and approvals

  • Only professional fields are kept for founders. Emails and phone numbers are dropped when data arrives.
  • A company or person counts as matched only on two independent signals; a namesake ends “unclear”.
  • Every verdict carries its reason code, confidence and sources, so a person can check it.
  • A missing record is never a contradiction. Thin public data gives “cannot verify”, never a penalty.
  • The founder email is drafted, held, and sent only after a person approves it, into a local test inbox.

Run it

Python 3.11. Put CRUSTDATA_API_KEY and OPENAI_API_KEY in .env (gitignored).

python -m venv .venv && .venv/bin/pip install -r requirements.txt
set -a; . ./.env; set +a
python cli.py run --request tests/decks/deck_a_request.json --out out/result.json
python cli.py resume <run_id> --out out/result.json     # after a kill
streamlit run ui/app.py                                   # run, claims, approvals, inbox, ledger
python -m pytest -q                                       # tests
python tests/eval/run_eval.py                             # offline score against the answer key

What does not work yet

  • Web claims count only when a page shows a publish date, so many customer and market claims end “cannot verify”.
  • Crustdata’s open-roles count has no date, so hiring claims stay open. Competition claims are never judged.
  • Only Deck A has a full answer key; decks B and C have no recorded evidence yet.
  • Rupee rates and most tolerances in config/rules.yaml are placeholder values.
  • Image-only slides are not read.

How it was built

Two people and several AI coding agents (Claude Code, Codex, Gemini), each owning its own folders, coordinated through one rules file, written decisions and handoff notes. 19 written decisions, 5 hard-rule violations caught in review before they reached main, and every failure logged in docs/INCIDENTS.md. Planning documents were written before 10:15 AM; no code was.
